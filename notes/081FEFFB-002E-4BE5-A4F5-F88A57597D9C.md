# Running the `hello` program

- type `./hello` at the keyboard, shell program reads each one into a register and then stores it in memory
- hit `enter` key on the keyboard, the shell loads the executable `hello` file by executing a sequence of instructions that copies the code and data in the `hello` object file from disk to main memory. including the string of characters `hello, world\n`
- using <mark>DMA</mark> to pass the data without passing through the processor
- the processor begins executing the instructions in the `hello` program's main routine
- copy the bytes in the `hello, world\n` string from memory to register file, and from there to the display device

# Process context switching

- shell process is running alone and waiting for input
- `hello` program: shell invoke a special function called `system call` passes the control to the OS
- OS saves shell's context and creates a new `hello` process and its context and then passes control to the new process
- after `hello` terminates, OS restores the context of the shell process and passes control back to it
- <u>the transition from one process to another is managed by <b><mark>OS kernel</mark></b></u>

# Amdahl’s Law

$$\begin{aligned}
T_{\mathrm{new}} &= (1-\alpha)T_{\mathrm{old}} + (\alpha T_{\mathrm{old}})/k \\
&= T_{\mathrm{old}}\left[(1-\alpha)+\alpha/k\right] \\
S &= T_{\mathrm{old}}/T_{\mathrm{new}} \\
S &= \frac{1}{(1-\alpha)+\alpha/k}
\end{aligned}$$

**Hyperthreading:** sometimes called simultaneous multi-threading, is a tech-nique that allows a single CPU to execute multiple flows of control. It involves having multiple copies of some of the CPU hardware, such as program counters and register files, while having only single copies of other parts of the hardware, such as the units that perform floating-point arithmetic. Whereas a conventional processor requires around 20,000 clock cycles to shift between different threads, a hyperthreaded processor decides which of its threads to execute on a cycle-by-cycle basis.
